# 仪表板

[English](../dashboard.md) | 简体中文 | [繁體中文](../zh-tw/dashboard.md)

「LiteLLM: 打开仪表板」打开一个面板, 一切尽在其中: 服务器、已发现的模型和扩展的设置, 顶部是显示整体连接状态的状态条。它是对扩展其余部分所用的同一批存储的一个视图, 因此你在这里做的任何事, 都同样可以通过 VS Code 设置和命令完成; 仪表板只是把它们放在了一处。

## 布局

- 顶部一条状态条: 整体连接状态、服务器和模型数量、上次同步, 以及「同步模型」按钮。标题旁有一个低调的「报告 Bug」操作, 打开预填了版本、平台和近期日志的 GitHub Issue。
- 三个标签页。服务器和模型共用第一个, 因为它们是同一工作流: 连接服务器, 查看其模型。第二个以可编辑的表单控件承载扩展的设置。第三个是诊断: 连接摘要, 加上反馈和文档链接。
- 设置编辑写入你的 VS Code 设置 (写入值已所在的作用域, 否则写入用户设置), 各按钮运行的命令与命令面板提供的相同。

## 服务器

服务器列表显示扩展知道的每个服务器: 在 `litellm-vscode-chat.servers` 设置中声明的条目, 以及只作为 VS Code 提供程序组存在的「外部」服务器 (在此扩展之外添加)。

每行的状态标记是四种状态之一:

| 状态 | 含义 |
|--------|---------|
| 已连接 | 发现成功 |
| 错误 | 最近一次检查失败 |
| 同步问题 | 服务器有应答, 但其最近一次设置同步报告了问题, 通常是[组更新限制](servers.md#servers-设置) |
| 未检查 | 已声明, 但尚未经过任何发现流程 |

「错误」或「同步问题」状态背后的错误文本会在表格下方的横幅中以可选中文本呈现; 恢复步骤见[故障排除](troubleshooting.md)。

添加/编辑表单在侧边面板中打开; 它写入 servers 设置, 因此这里的编辑和 settings.json 中的编辑是同一回事。「保存」旁的「测试连接」会在你提交前探测草稿 - 用当前输入的 URL 和凭据发出一次发现调用, 回答「已连接 - 12 个模型」或确切错误, 且不保存任何内容。在外部行上,「编辑」会把它采用进设置; 参见[服务器](servers.md#外部服务器与采用)。

对每个密钥字段, 表单让你在 VS Code 密钥存储 (默认) 和内联设置值之间选择:

- 密钥存储中的密钥从不回显到仪表板; 对它们, 表单显示值存放在哪里, 不显示值是什么。
- 内联值会预填到编辑表单中, 遮盖在「显示」开关之后: 它们本来就以明文存在于你的 settings.json 中, 因此表单不会透露设置编辑器看不到的任何内容。
- 编辑时, 清空的密钥字段会保留已存储的值; 删除要用表单显式的「保存时删除已存储的...」复选框 (参见[密钥与密钥存储](servers.md#密钥与密钥存储))。

### 通知

- **「参数未生效」** (服务器行上的徽章, 表格下方有对应横幅): 条目声明了每服务器模型参数, 但为它提供服务的提供程序组不带有条目的标签化标识 (组早于条目标签, 或重命名留下了过期的组), 因此这些参数没有被应用。修复方法是从模型文件 (chatLanguageModels.json) 中删除该组的对象、重新加载窗口并重新同步 - 或者给条目改个标签; 步骤见[故障排除](troubleshooting.md#每服务器模型参数未生效)。
- **采用外部服务器之后**, 一次性通知会提醒你原组仍然存在, 在你从模型文件中删除其对象 (通知的按钮会打开它) 并重新加载窗口之前, 它的模型会重复显示。

## 模型

你的服务器报告的每个模型, 即注册到 Copilot Chat 的模型, 呈现在一张可排序、可筛选的表格中, 带有 token 限制、定价和能力说明。

- 单击服务器表格中某个服务器的模型数量, 会把这张表收窄到该服务器的模型; 筛选框旁的小标签显示当前的筛选范围, 并可清除它。
- 每行带有一个复制操作 (悬停可见), 复制模型的确切 ID, 也就是 [`modelParameters` 前缀](model-parameters.md#前缀匹配与服务器限定)所匹配的对象。
- 列表有缓存 ([discoveryCacheTtl](settings.md#模型列表缓存));「同步模型」按钮立即重新询问服务器。

表格各列来自哪里、每个能力门控什么、模型为何可能缺失, 见[模型与能力](models.md)。

### 生效参数

每行低调的「参数」操作 (悬停可见) 打开一个侧边面板, 回答一个问题: 发往这个模型的请求实际会携带什么?

- 表格列出匹配该模型的每个已配置参数、它的值, 以及是哪一层设置的 -「服务器条目「Team A」- gpt-4」或「设置 - gpt-4」, 并指明胜出的前缀键。当更高层覆盖了更低层时, 落败的值以删除线显示在下方。
- 当限定到服务器的设置键胜出时, 被它取代的整个未限定记录会列为「未应用」- 限定键会整体取代记录, 而不是与之合并 (参见[前缀匹配](model-parameters.md#前缀匹配与服务器限定))。
- 扩展拒绝转发的键 (提供程序拥有的字段、以 `_` 开头的键) 以弱化样式显示, 并给出原因。
- `max_tokens` 一行始终存在, 说明其值和来源: 你的配置、服务器声明的输出限制, 或加了上限的默认值。

该面板用请求路径运行的同一份解析代码渲染, 因此不可能偏离真实请求。有两样它确实无法显示: 聊天客户端在每个请求上设置的运行时选项 (它们覆盖列出的任何转发参数), 以及推理模型在「配置模型」(Configure Model) 中的选择, 后者由 VS Code 在其侧存储。

## 设置

设置标签页把原生设置编辑器显示的同一批设置渲染为表单行, 带默认值和「重置」操作。

- 有两个设置在这里比在设置 UI 中更容易编辑: `modelParameters` 和 `headers` 是原生设置 GUI 无法编辑的对象, 因此仪表板为它们提供行编辑器。
- 模型参数的值是 JSON (`0.2`、`true`、`"text"`、`["stop"]`); 无效输入会被标记, 在每一行都能解析之前,「应用」保持禁用。
- 由于 VS Code 会跨作用域合并对象设置, 每个记录编辑器一次只操作一个作用域 (你的编辑写入的那个), 并把其他作用域的条目以只读方式列出, 因此应用更改永远不会把用户作用域的值复制进工作区文件。
- 标头值是设置, 不是密钥: 它们的显示方式与设置编辑器完全相同, 因此请把机密标头放在用户作用域而非工作区作用域。

## 诊断

诊断标签页汇集各种支持入口; 命令面板中的「LiteLLM: 显示诊断信息」会把仪表板直接打开到这里。

- 一份为整体复制进 Bug 报告而写的连接摘要: 与状态条相同的结论、已配置服务器数量、以绝对时间戳显示的上次检查 (附相对时间), 以及每个服务器一行结果 ("OK (12 models)", 否则为错误文本), 外加一个「测试连接」按钮。如果安装中带有自身没有对应行的迁移前服务器, 还会看到一个 "Legacy registry servers" 计数。
- 「报告 Bug」打开预填了版本、平台和近期日志的 GitHub Issue - 与标题栏按钮相同的操作。
- 「请求新功能」、「为此扩展评分」、「文档」与「GitHub 仓库」是普通链接。
