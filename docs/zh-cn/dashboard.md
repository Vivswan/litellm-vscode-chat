# 仪表板

[English](../dashboard.md) | 简体中文 | [繁體中文](../zh-tw/dashboard.md)

"LiteLLM: Open Dashboard" 打开一个面板, 一切尽在其中: 服务器、已发现的模型、用量与预算, 以及扩展的设置, 顶部是显示整体连接状态的状态条。它是对扩展其余部分所用同一批存储的一个视图, 因此你在这里做的任何事, 都同样可以通过 VS Code 设置和命令完成; 仪表板只是把它们放在一处, 附上原始 JSON 给不了的验证与来源信息。

## 布局

- 顶部一条状态条: 整体连接状态、服务器和模型数量、上次同步, 以及「同步模型」按钮。标题旁一个低调的「报告 Bug」操作, 打开预填了版本、平台和近期日志的 GitHub Issue。
- 四个标签页。**服务器和模型**共用第一个, 因为它们是同一条工作流: 连接服务器, 看它的模型。**用量**显示支出对预算。**设置**以可编辑的表单控件承载扩展的设置。**诊断**是连接摘要、扩展发现的配置问题, 以及反馈与文档链接。
- 设置编辑写入你的 VS Code 设置 (写到值已所在的作用域, 否则写到用户设置), 按钮运行的是命令面板提供的同一批命令。
- 各区块可从外部直达: 命令会落在它们关涉的区块上, 通知按钮把仪表板打开到「服务器与模型」- 只有预算警报的「打开用量」按钮例外, 它深层链接到用量区块 ([深层链接](#深层链接))。

## 服务器

服务器列表显示扩展知道的每个服务器: 在 [`litellm-vscode-chat.servers` 设置](servers.md#条目参考)中声明的条目, 以及只作为 VS Code 提供程序组存在的「外部」服务器 (在本扩展之外添加 - 见[采用](servers.md#外部服务器与采用))。被已删除条目隐藏的组折叠进「隐藏的组」一行, 附「取消隐藏」操作 ([生命周期](servers.md#生命周期-重命名删除与隐藏的组))。

每行的状态标签是六种状态之一:

| 状态 | 含义 |
|--------|---------|
| 已连接 | 发现成功 |
| 错误 | 上次检查失败 |
| 同步问题 | 服务器有应答, 但上次设置同步报告了问题, 典型的是[组更新限制](servers.md#生命周期-重命名删除与隐藏的组) |
| 预期失败 | 发现只在条目的 [`discovery.expectedFailures`](servers.md#发现与预期失败) 声明的类别中失败, 且没有声明的模型可提供 |
| 配置错误 | 条目本身无效 - 例如多于一种[身份验证形式](servers.md#身份验证) - 修复前不被使用 |
| 未检查 | 已声明, 但还没有发现轮次看过它 |

「错误」或「同步问题」状态背后的错误文本在表格下方以可选中的横幅呈现; [故障排除](troubleshooting.md#常见问题)覆盖恢复步骤。一处有意的柔化: 预期的发现失败从不显示为红色 - 当条目的[声明模型](servers.md#声明的模型)仍在提供时, 该行保持「已连接」, 什么都没声明时显示「预期失败」。

### 通知

- **「params inactive」(参数未生效)** (服务器行上的徽章, 加表格下方对应的横幅): 条目声明了每服务器模型参数, 但服务它的提供程序组不携带条目的标签化标识 (组早于条目标签, 或重命名留下了过期组), 所以那些参数没有被应用。每服务器能力、声明的模型或预期失败因同一原因未生效的条目, 得到孪生的「capabilities inactive」徽章; 未生效的自定义标头则有自己的「headers inactive」徽章。三者的修复相同: 从模型文件 (chatLanguageModels.json) 删除该组的对象, 重新加载窗口并重新同步 - 或给条目换个标签; [故障排除](troubleshooting.md#每服务器模型参数未生效)有步骤。
- **什么都没声明的预期发现失败**有自己的横幅: 发现只在条目预期的类别中失败, 但条目的 `discovery.declared` 列表为空, 所以服务器不提供任何模型; 横幅指向[声明的模型](servers.md#声明的模型)。
- **采用外部服务器之后**, 一次性通知提醒你原组仍然存在, 在你从模型文件删除其对象 (通知的按钮会打开它) 并重新加载窗口之前, 它的模型会出现两次。

## 服务器表单

「添加」和「编辑」在侧面板中打开同一个表单。它写入 `servers` 设置, 所以在这里做的编辑和在 settings.json 里做的编辑是同一回事; 表单的价值在于随打随校验条目的形状, 而不是保存之后才发现。

**标识** - `label` (选择器名称) 和 `baseUrl`。表单会提醒你去掉 `/v1` 后缀; 扩展自行追加 ([原因](servers.md#条目参考))。

**身份验证** - 身份验证形式的选择器: 无、API 密钥、虚拟密钥或 OAuth。这个选择器*就是*[恰好一种形式规则](servers.md#身份验证): 原始 JSON 要你自己守规矩, 表单则让第二种形式根本无从设置。选择 OAuth 会展开它的字段和可选的伴随凭据 - 随 bearer 令牌一起发送的 `apiKey` 或 `virtualKey`, 给同时检查两个凭据的网关。

**密钥** - 每个可作密钥的字段都提供逐字段选择: VS Code 密钥存储 (默认) 或内联设置值:

- 密钥存储中的密钥从不回显到仪表板; 表单为它们显示值存放在哪里, 不显示值是什么。
- 内联值会预填到编辑表单, 遮盖在「显示」开关之后: 它们本来就以明文存在于你的 settings.json 中, 所以表单不会泄露设置编辑器看不到的任何东西。
- 编辑时, 清空的密钥字段保留存储的值; 删除密钥是表单显式的「删除已存储的...」复选框 (见[密钥与密钥存储](servers.md#密钥与密钥存储))。

**每服务器模型配置** - 表单以两个区块承载条目的 [`models` 对象](servers.md#每服务器模型配置):

- *此服务器的模型参数*: 以[匹配器](models.md#模型匹配)为键的行, 值为 JSON (`0.2`、`true`、`["stop"]`), 逐行验证。每行有一个**强制**复选框 - 被强制的字段胜过聊天客户端的运行时选项和模型选择器的配置 ([参数](models.md#参数))。在提供程序拥有的键 (`model`、`messages`、`stream` 等) 上, 强制被禁用并注明原因 - 扩展从不允许任何东西覆盖它们。
- *此服务器的模型能力*: 同款行编辑器, 用于能力覆盖。每行有一个**回退**复选框 - 回退字段应用在服务器报告*之下*而非之上 - 以及用于 `_openrouter_model` 指令的 OpenRouter 目录选择器 ([能力](models.md#能力))。

**发现** - 面向发现看不见的东西的两个控件, 并排放置因为它们常常组合 ([无发现能力网关的配方](servers.md#发现与预期失败)):

- *声明的模型* (`discovery.declared`): 一个纯列表, 列出即使发现列不出也要注册的精确模型 ID ([声明的模型](servers.md#声明的模型))。旧版本中声明是能力行上的「声明此模型」开关; 迁移把那些移进了这个列表。
- *预期失败*: 此服务器已知不提供的终结点的复选框 (`modelListing`、`modelInfo`)。

**标头** - 条目 `headers` 对象的行编辑器: 发往此服务器的每个请求上的额外 HTTP 标头 (路由标签、跟踪标头)。条目自己的[身份验证](servers.md#身份验证)标头在冲突时胜出, 所以自定义 `Authorization` 无法挤掉配置的凭据。标头值是设置, 不是密钥 - 它们以明文放在 settings.json 里; 凭据属于身份验证形式, 后者可以存放在密钥存储中。

**预算** - 驱动[用量警报](usage.md#预算)的手动美元预算。

**测试连接**在「保存」旁边, 在你提交之前探测草稿 - 用当前输入的 URL 和凭据发出一次发现调用, 回答「已连接 - 12 个模型」或确切的错误, 什么都不保存。探测遵循草稿的预期失败和声明的模型, 所以无发现能力的网关报告它将提供什么, 而不是硬失败。扩展认得的设置类失败 (错误的基础 URL、不可达的代理、被拒的密钥) 会在消息下方附上指向[故障排除指南](troubleshooting.md#常见问题)对应小节的链接。

外部行上的「编辑」是采用操作; 见[服务器](servers.md#外部服务器与采用)。

## 模型

你的服务器报告的每个模型, 按注册给 Copilot Chat 的样子, 呈现在可排序、可筛选的表格中, 带 token 限制、定价和能力注记。列从哪里来、每个能力门控什么、模型为什么可能缺失: [模型](models.md#模型如何出现)。

- 单击服务器表格中某服务器的模型数, 会把这张表收窄到该服务器的模型; 筛选框旁的标签片显示当前范围并可清除。
- 每行携带一个复制操作 (悬停可见), 复制模型的精确 ID - 你的[匹配键](models.md#模型匹配)所匹配的字符串。
- 由条目的[声明列表](servers.md#声明的模型)注册而非在服务器上发现的模型, 带「已声明」徽章。
- 列表有缓存 ([`discovery.cacheTtl`](settings.md#参考)); 「同步模型」按钮立即重新询问服务器。

### 生效参数

每行低调的「参数」操作 (悬停可见) 打开一个侧面板, 回答一个问题: 发往这个模型的请求实际会携带什么?

- 表格列出匹配该模型的每个已配置参数、它的值, 以及设置它的层和键 - `服务器条目 "prod" - 键 "gpt-5*"` 或 `设置 - 键 "*"` - 点名胜出的[匹配器](models.md#模型匹配)。当更具体的匹配或更高的层覆盖了另一个值时, 落败的值以删除线显示在下方, 所以在你意料之外触发的匹配器一眼就能找到元凶。
- 被强制的字段标记为强制: 它们连聊天客户端的运行时选项都会胜过 ([完整优先级](models.md#参数))。
- 扩展拒绝转发的键 (提供程序拥有的字段、以 `_` 开头的键) 以弱化样式呈现并注明原因。
- 一行 `max_tokens` 始终在场, 说明该值及其来处: 你的配置、服务器声明的输出限制, 还是封顶的默认值。

面板由请求路径运行的同一套解析代码渲染, 所以它不可能偏离真实请求。两样它诚实承认无法展示的东西: 聊天客户端在每个请求上设置的运行时选项 (它们覆盖列出的任何*未强制*参数), 以及推理模型的 Configure Model 选择, 后者由 VS Code 存在自己那边。

### 生效能力

「参数」操作的孪生 - 每行低调的「能力」操作 - 回答另一个问题: 扩展认为这个模型能做什么, 为什么?

- 每个能力字段列出解析值和来源 - 某服务器条目或全局 `models.capabilities` 记录 (点名胜出的匹配键)、服务器自己的报告、标记为回退的字段、OpenRouter 目录条目 (显式 `_openrouter_model` 或精确 ID 匹配)、「上下文减输出」派生, 或内置默认值 - 被覆盖的值显示在胜出者下方 (完整[优先级](models.md#能力))。
- 表格下方一行说明输出限制是不设上限发出 (用户设置或服务器声明), 还是封顶 4096 (猜测的默认值)。
- 匹配到的记录中的配置问题 - 未知字段、无效值、无效的正则匹配器、目录不认识的 `_openrouter_model` ID - 在这里、在受影响的行旁边指出。

它由注册路径运行的同一个解析器渲染, 所以它显示的就是告诉 Copilot Chat 的内容。

## 用量区块

支出对预算, 按服务器, 覆盖每个其 LiteLLM 实例跟踪支出的服务器 - 没有数据库的服务器干脆不出现, 而当你的服务器都不跟踪支出时, 该区块会明说, 而不是显示空图表。

每张服务器卡片显示支出对预算进度条和百分比、生效预算与密钥报告预算 (两者不同时)、预算的重置日期, 以及 - 当服务器提供每日活动数据时 - 请求数、成功率和缓存命中率。「立即刷新」按钮立即获取 (获取进行中禁用) 并显示数据上次更新时间; 过期数据保持可见, 标注其年龄, 原因已知时还点名原因 (「- 上次刷新失败」「- 用量访问被拒绝」)。当一次显式刷新在每个服务器上都失败时, 会有一条警告弹窗说明; 按服务器的详细信息留在卡片上。

打开仪表板总会获取新的用量数据, 即使后台轮询关闭。深入内容 - 扩展读什么、从哪里读、两个预算来源如何互动、轮询与新鲜度、警报阈值、状态栏项 - 在[用量与预算](usage.md)页面。

## 设置

设置区块渲染的是原生设置编辑器显示的同一批设置, 分组方式相同 (服务器、模型、聊天、发现、用量、UI), 以表单行呈现, 带单位、默认值和「重置」操作。已配置的行会说明其值存放在哪里 (「已在用户设置中修改」); 「重置」从该作用域删除值, 让下一作用域的值或默认值显现。

- 对象形态的设置 - [`models.parameters`](settings.md#参考) 和 [`models.capabilities`](settings.md#参考) - 在这里获得行编辑器, 因为原生设置 GUI 无法编辑对象。它们使用与[服务器表单](#服务器表单)的每服务器区块相同的编辑器: 匹配键、逐行验证的 JSON 值 (每行都解析通过之前「应用」保持禁用), 以及逐行的强制/回退复选框。(自定义 HTTP 标头是按服务器的, 不是全局的: 它们存放在条目上, 在[服务器表单](#服务器表单)中编辑。)
- 由于 VS Code 跨作用域合并对象设置, 每个记录编辑器一次只操作一个作用域 (你的编辑写入的那个), 其他作用域的条目以只读列出, 所以应用更改永远不会把用户作用域的值复制进工作区文件。
- [`models.openRouterCatalog`](models.md#openrouter-目录) 行携带一条状态线 - 目录的大小和上次更新时间 - 和一个「刷新」按钮 (与 "LiteLLM: Refresh OpenRouter Catalog" 相同的操作)。设置关闭时该行休眠并附提示; 刷新失败在状态线中报告, 从不弹窗。

## 诊断

诊断区块汇集支持界面; 命令面板中的 "LiteLLM: Show Diagnostics" 把仪表板直接打开到它。

- 一份为整体粘贴进 Bug 报告而写的连接摘要: 状态条显示的同一结论、已配置服务器数量、以绝对时间戳表示的上次检查 (附相对回显), 以及每个服务器一行结果 ("OK (12 models)", 否则是错误文本), 外加「测试连接」按钮。携带无自有行的迁移前服务器的安装还会看到「旧版注册表服务器」计数。
- 配置诊断: 扩展在你的设置中发现的问题, 每个都在这里以及它关涉的行旁边呈现 ([下文](#配置诊断))。
- 「报告 Bug」打开预填版本、平台和近期日志的 GitHub Issue - 与标题按钮相同的操作。
- 「请求功能」「为扩展评分」「文档」和「GitHub 仓库」是普通链接。

### 已解析模型

诊断标签页还渲染扩展预计算的解析表 - 每个已注册模型最终得到的确切能力和参数, 覆盖所有服务器, 早于任何请求。同一份数据的两个视图:

- **继承树**: 你的匹配键画成一棵树 - 每条记录挂在它的下一个更宽匹配之下, 模型作为叶子挂在最具体的匹配之下 - 每个节点标出自己的字段、`_inheritable` 标记, 以及画在被切断分支上的 `_inherit_from: false` 屏障。一眼回答「gpt-5.6 的 temperature 为什么是这个」: 沿它的分支向上走。

```text
*  temperature 0.7, top_p 0.9  (inheritable)
├─ gpt-5*  temperature 0.3  (inheritable)  [inheritance stops here]
│  ├─ gpt-5.6  max_tokens 8192   -> 8192 - 0.3
│  └─ gpt-5, gpt-5.7, ...        -> 0.3
├─ claude-4  temperature 1.0     -> 1.0 - top_p 0.9
└─ (everything else)             -> 0.7 - 0.9
```

- **扁平表**: 每模型一行, 列出最终解析值, 每个值带来源标签片 (自有、继承自 `key`、强制、回退、服务器、目录、底线), 一个筛选框 (按模型 ID 或匹配键 - 「显示 `gpt-5*` 碰过的一切」), 以及逐行跳转到该模型的[生效值检查器](#生效参数)。

关于树的一条诚实说明: 它是对着你的服务器*此刻*提供的模型画的。记录节点 - 尤其是正则键 - 显示的是它当前匹配到的现存模型, 不是它可能匹配的一切, 所以模型列表变了树也会变。要得到关于某一个模型的权威答案, 扁平表的该模型行和检查器才是正典视图。

完全没有配置匹配记录时, 扁平表仍列出每个模型 - 值随即来自服务器、目录和内置底线 - 树则塌缩为挂在隐式根下的模型, 附一条「不存在记录」的提示。

两者渲染的都是请求路径使用的同一张预计算表, 所以你看到的就是将要发送的。该视图只存在于仪表板本地 - 从不包含在 GitHub 问题报告中。

### 配置诊断

设置问题从不无声失败; 每一个都作为诊断呈现, 带出问题的键和修复方法:

| 诊断 | 含义 | 修复 |
|---|---|---|
| 无效的正则匹配器 | 一个 `/斜杠包裹/` 的记录键无法解析为正则表达式; 该键被忽略 | 修正模式 ([匹配](models.md#模型匹配)) |
| 不可强制的键 | `_force` 点名了提供程序拥有的字段, 任何东西都不得覆盖它; 对该字段的强制被忽略 | 把该字段从强制列表中去掉 ([参数](models.md#参数)) |
| 身份验证配置错误 | 某服务器条目配置了多于一种身份验证形式; 修复前条目不被使用 | 恰好保留一种形式 ([身份验证](servers.md#身份验证)) |
| 旧版限定键 | 某全局记录键仍在使用已移除的 `"<baseUrl>/matcher"` 服务器限定语法; 它永远匹配不到模型 ID, 处于休眠 | 移入那个服务器条目自己的记录 ([迁移](models.md#从前缀键迁移)) |
| 休眠的全局标头 | 迁移在已移除的全局 `headers` 设置中发现了值, 却没有可接收它们的服务器条目; 它们没有应用到任何东西 | 把标头加到服务器条目上, 然后删除旧的全局设置 ([迁移](settings.md#重命名与移除的设置)) |
| 未知的 `_inherit_from` 键 | `_inherit_from` 列表点名了不存在的记录键; 跳过该名字, 列表其余部分照常生效 | 把名字改成精确的记录键 ([匹配](models.md#哪条记录生效)) |

## 状态栏项

扩展最多拥有两个状态栏项; 仪表板是它们的点击落点。

- **连接项**在一切健康时读作 `$(check) LiteLLM`, 工具提示里有服务器和模型数量; 错误和部分状态会改变图标和工具提示, 而工具提示的行是为粘贴进问题报告而写的。单击它打开仪表板。(旧版本把模型数放在项的文本里; 现在它在工具提示里, 让状态栏保持安静。)
- **用量项**显示最差新鲜服务器的支出百分比, 只在有可信内容时出现; 单击它打开[用量区块](#用量区块)。它的完整行为 - 模式、阈值、新鲜度规则 - 在[用量与预算](usage.md#状态栏)中规定。
