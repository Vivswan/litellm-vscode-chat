# 仪表板

[English](../dashboard.md) | 简体中文 | [繁體中文](../zh-tw/dashboard.md)

"LiteLLM: Open Dashboard" 打开一个面板, 一切尽在其中: 服务器、已发现的模型、用量与预算, 以及扩展的设置, 整体连接状态钉在旁边的导航栏上。它是对扩展其余部分所用同一批存储的一个视图, 因此你在这里做的任何事, 都同样可以通过 VS Code 设置和命令完成; 仪表板只是把它们放在一处, 附上原始 JSON 给不了的验证与来源信息。

## 布局

- 左侧一条导航栏: 各个页面的入口, 每个都在有数可显示时带着它所关心的实时数字 (服务器数、模型数、待处理问题数), 其下是所有服务器的总体连接状态和上次同步时间, 在旁边的页面滚动时一直留在屏幕上。导航栏底部有一个「同步模型」按钮和一个低调的「报告 Bug」操作; 后者打开预填了版本、平台和近期日志的 GitHub Issue。
- 五个页面。**服务器**是你的条目、它们的健康状况和支出对预算, 每个服务器的问题写在所属行的下方 (警告级的预算提示除外, 它待在该行抽屉里的支出事实旁 - 该行着色的计量条已经发出这一信号), 完整清单 (包括条目自身的模型记录) 收在该行的展开抽屉里。**模型**是那些服务器报告的一切, 服务器抽屉里的模型数会跳转到这里并收窄到该服务器。**功能**承载扩展在聊天之外的功能 - 内联补全、提交消息生成、PR 描述生成、咨询工具、快速修复、评审评论和聊天参与者 - 各自带启用开关、模型选择和功能专属的行 ([功能](#功能))。**设置**以可编辑的表单控件承载扩展其余的设置。**诊断**是扩展发现的配置问题、[已解析模型](#已解析模型), 以及支持工具与链接。
- 设置编辑写入你的 VS Code 设置 (写到值已所在的作用域, 否则写到用户设置), 按钮运行的是命令面板提供的同一批命令。
- 各区块可从外部直达: 命令会落在它们关涉的区块上, 通知按钮把仪表板打开到「服务器」- 包括预算警报的「打开用量」按钮, 因为支出如今就在那里 ([深层链接](#深层链接))。
- 窄面板会重排而不是横向滚动, 下限为 320px。窗口窄于 1000px 时, 导航栏折叠成图标栏, 就像 VS Code 自己的活动栏那样; 每个导航项的名称、整体连接状态和同步时间都留在可访问名称里并以提示形式出现, 较宽的行则折成多行, 而不是丢掉信息。

## 服务器

服务器列表显示扩展知道的每个服务器: 在 [`litellm-vscode-chat.servers` 设置](servers.md#条目参考)中声明的条目, 以及只作为 VS Code 提供程序组存在的「外部」服务器 (在本扩展之外添加 - 见[采用](servers.md#外部服务器与采用))。被已删除条目隐藏的组折叠进「隐藏的组」一行, 附「取消隐藏」操作 ([生命周期](servers.md#生命周期-重命名删除与隐藏的组))。区块标题带一行摘要 - 服务器数、多少行需要处理、新鲜行中最高的预算占用 (下方可见过期数字时标注「不含已过时的行」)、后台轮询是否关闭 - 以及「添加服务器」和一个立即获取用量数据的「立即刷新」按钮 (获取进行中时禁用)。

每一行是一个可读区块 - 标签、状态、URL、模型数、支出和凭据徽章 - 展开后是包含该行完整清单的抽屉: 基础 URL、凭据类型、模型数 (作为链接打开收窄到该服务器的[模型](#模型)页)、发现上次检查它的时间, 以及当服务器跟踪支出时的每一项用量事实 ([用量面板](usage.md#用量面板))。收起的行上, 支出显示为共享严重度色调下的预算百分比加一条小计量条; 没有预算给百分比意义时显示为纯金额; 代理不跟踪支出的服务器显示空单元格。

每行的状态标签是六种状态之一:

| 状态 | 含义 |
|--------|---------|
| 已连接 | 发现成功 |
| 错误 | 上次检查失败, 且服务器未提供任何模型 |
| 同步问题 | 服务器有应答, 但上次设置同步报告了问题 - 典型的是[组更新限制](servers.md#生命周期-重命名删除与隐藏的组) - 或上次检查失败, 但[声明模型](servers.md#声明的模型)或宽限窗口内最后已知的列表仍在提供 |
| 预期失败 | 发现只在条目的 [`discovery.expectedFailures`](servers.md#发现与预期失败) 声明的类别中失败, 且没有任何模型在提供 - 没有声明的模型, 宽限窗口也没有存留 |
| 配置有误 | 条目本身无效 - 例如多于一种[身份验证形式](servers.md#身份验证) - 修复前不被使用 |
| 未检查 | 已声明, 但还没有发现轮次看过它 |

每行的问题直接呈现在该行下方, 最严重的在前。每一条都以后果开头 ("prod 未提供任何模型: ..."), 附上服务器自己的错误文本 (如果有), 并就地给出对应的操作 - 「重试」「打开条目」「在 settings.json 中修复」「声明模型」「打开模型文件」「立即刷新」或故障排除链接。用量问题按同一标尺分级: 密钥被拒绝读取自身用量, 以及预算越过阈值, 都是计入的问题; 而一次瞬时的刷新失败是安静的建议性行, 但仍然完整呈现 (标题、技术细节和「立即刷新」), 因为它会在下一次轮询时自行消除。当有行需要处理时, 区块标题的摘要会计入它 ("2 个需要处理"); 安静的建议性行只陈述无需处理的事实, 不计入该数字。[故障排除](troubleshooting.md#常见问题)覆盖恢复步骤。一处有意的柔化: 仍在提供的预期发现失败 - 提供[声明模型](servers.md#声明的模型), 或过期窗口期内最后已知的列表 - 不算问题: 该行保持「已连接」, 配一条低调的建议性行说明这次预期中的失败。完全没有东西可提供时, 该行像任何不提供模型的服务器一样显示为红色, 结论读作「预期失败」。

### 通知

- **条目配置未生效** (服务器行下方的一条诊断行): 为条目提供服务的提供程序组可能不携带条目的标签化标识 (组早于条目标签, 或重命名留下了过期组), 所以条目声明的一部分内容可能未被应用 - 按服务器的模型参数、按服务器的能力、声明的模型与预期失败、自定义标头, 或 `apiVersion` 覆盖 (请求回退到自动规则)。该行会点名究竟哪些部分未生效, 旁边就是「打开模型文件」操作。修复对所有情况都相同: 从模型文件 (chatLanguageModels.json) 删除该组的对象, 重新加载窗口并重新同步 - 或给条目换个标签; [故障排除](troubleshooting.md#每服务器模型参数未生效)有步骤。
- **什么都不提供的预期发现失败**是行下方的一条阻断性诊断行: 发现只在条目预期的类别中失败, 且没有东西通过它提供 - 条目的 `discovery.declared` 列表为空, 过期窗口期内也没有保留的模型 - 所以服务器不提供任何模型; 该行的「声明模型」操作会打开条目 ([声明的模型](servers.md#声明的模型))。
- **采用外部服务器之后**, 一次性通知提醒你原组仍然存在, 在你从模型文件删除其对象 (通知的按钮会打开它) 并重新加载窗口之前, 它的模型会出现两次。

## 服务器表单

「添加」和「编辑」把同一个表单作为主窗格中的一个页面打开, 导航栏仍在旁边: 一个扁平的页面, 条目的每个部分 - 连接、身份验证、模型参数、模型能力、发现、标头与预算、MCP - 都带着自己的标题从上到下排开, 没有任何内容折叠在展开控件后面。它写入 `servers` 设置, 所以在这里做的编辑和在 settings.json 里做的编辑是同一回事; 表单的价值在于边输入边校验条目的结构, 而不是保存之后才发现问题。每个字段的提示就在它旁边, 出错时错误占据提示的位置 (所以输入时页面不会跳动); 钉在底部的保存栏写明条目将写入哪个设置, 并统计还有多少处未保存。离开这一页 (顶部的返回路径、导航栏、Esc 或「放弃更改」) 不会立即生效: 有未保存的编辑时会先询问, 只有显式的「放弃」才会丢弃草稿。焦点跟着你进来, 也跟着你回去, 回到你打开时所在的那一行。

**标识** - `label` (选择器名称) 和 `baseUrl`。扩展会自行追加 `/v1`; 若 URL 已以 `/v1` 或 `/v2` 这样的版本段结尾, 则按原样使用; `apiVersion` 字段可覆盖两者 ([原因](servers.md#条目参考))。

**身份验证** - 身份验证形式的选择器: 无、API 密钥、虚拟密钥或 OAuth。这个选择器*就是*[恰好一种形式规则](servers.md#身份验证): 原始 JSON 要你自己守规矩, 表单则让第二种形式根本无从设置。选择 OAuth 会展开它的字段和可选的伴随凭据 - 随 bearer 令牌一起发送的 `apiKey` 或 `virtualKey`, 给同时检查两个凭据的网关。

**密钥** - 每个可作密钥的字段都提供逐字段选择: VS Code 密钥存储 (默认) 或内联设置值:

- 密钥存储中的密钥从不回显到仪表板; 表单为它们显示值存放在哪里, 不显示值是什么。
- 内联值会预填到编辑表单, 遮盖在「显示」开关之后: 它们本来就以明文存在于你的 settings.json 中, 所以表单不会泄露设置编辑器看不到的任何东西。
- 编辑时, 清空的密钥字段保留存储的值; 删除密钥是表单显式的「删除已存储的...」复选框 (见[密钥与密钥存储](servers.md#密钥与密钥存储))。
- 保存一次把基础 URL 移离已存储密钥所属地址的编辑时, 会先询问 - 在新 URL 上使用同一密钥, 还是清除它 ([更改服务器的 URL](servers.md#更改服务器的-url))。

**每服务器模型配置** - 表单以两个区块承载条目的 [`models` 对象](servers.md#每服务器模型配置):

- *此服务器的模型参数*: 每个[匹配器](models.md#模型匹配)一行 - 匹配键、它匹配到什么, 以及以低调文本呈现的字段 (`temperature 0.2`), 指针悬停或获得焦点时变成控件, 加号 `[+]` 用来新增。单击一个字段片会打开一个小编辑器 - JSON 值、一个**强制**开关 (被强制的字段胜过聊天客户端的运行时选项和模型选择器的配置, [参数](models.md#参数); 在提供程序拥有的键上禁用并注明原因)、一个**可继承**开关, 以及「删除字段」。铅笔图标打开完整的匹配器编辑器。
- *此服务器的模型能力*: 同样的行, 用于能力覆盖。字段名是自由的 (词汇表是开放的, [能力](models.md#能力字段)); 扩展不消费的名字会在你输入时得到一条不拦截的「可能是笔误」提示 - 仅当服务器观察到的 `/model/info` 键集已知、非空且不含该名字时 - 无论如何都按原样应用。能力字段片带一个**后备**开关 - 后备字段应用在服务器报告*之下*而非之上 - `_openrouter_model` 指令则呈现为目录字段片, 它的编辑器就是 OpenRouter 目录选择器 ([能力](models.md#能力))。

**发现** - 面向发现看不见的东西的两个控件, 放在同一区块因为它们常常组合 ([无发现能力网关的配方](servers.md#发现与预期失败)):

- *声明的模型* (`discovery.declared`): 一个纯列表, 列出即使发现列不出也要注册的精确模型 ID ([声明的模型](servers.md#声明的模型))。旧版本中声明是能力行上的「声明此模型」开关; 迁移把那些移进了这个列表。
- *预期失败*: 此服务器已知不提供的终结点的复选框 (`modelListing`、`modelInfo`)。

**标头** - 条目 `headers` 对象的行编辑器: 发往此服务器的每个请求上的额外 HTTP 标头 (路由标签、跟踪标头)。条目自己的[身份验证](servers.md#身份验证)标头在冲突时胜出, 所以自定义 `Authorization` 无法挤掉配置的凭据。标头值是设置, 不是密钥 - 它们以明文放在 settings.json 里; 凭据属于身份验证形式, 后者可以存放在密钥存储中。

**预算** - 驱动[用量警报](usage.md#预算)的手动预算, 以服务器自身的计费货币计。

**MCP** - 独立的区块: 一个开关, 让此服务器自身的 [MCP 工具](servers.md#mcp-工具)可在聊天中使用, 以及要发布的端点。端点留空时, 提示会写明由基础 URL 推导出的确切地址。

**测试连接**就在它所探测的基础 URL 旁边, 在你提交之前试用草稿 - 用当前输入的 URL 和凭据发出一次发现调用, 回答「已连接 - 12 个模型」或确切的错误, 什么都不保存。探测遵循草稿的预期失败和声明的模型, 所以无发现能力的网关报告它将提供什么, 而不是硬失败。扩展认得的设置类失败 (错误的基础 URL、不可达的代理、被拒的密钥) 会在消息下方附上指向[故障排除指南](troubleshooting.md#常见问题)对应小节的链接。

外部行上的「编辑」是采用操作; 见[服务器](servers.md#外部服务器与采用)。

## 模型

你的服务器报告的每个模型, 按注册给 Copilot Chat 的样子, 每个占两行: 名称加它的系列和服务器, 然后是一行低调的规格说明 - token 限制、每百万 token 价格, 以及模型能做什么。排序和筛选控件在列表上方。这些值从哪里来、每个能力门控什么、模型为什么可能缺失: [模型](models.md#模型如何出现)。

- 单击服务器页上某服务器抽屉里的模型数, 会打开这一页并收窄到该服务器; 筛选框旁的标签片显示当前范围并可清除。
- 每行携带一个复制操作 (悬停可见), 复制模型的精确 ID - 你的[匹配键](models.md#模型匹配)所匹配的字符串。
- 单击一行会就地展开它的详情 - 确切的 token 限制、原始模型 ID、包括缓存和长上下文在内的每一档价格, 以及每个能力的是与否。一次只展开一行, 页面不会跳转。
- 由条目的[声明列表](servers.md#声明的模型)注册而非在服务器上发现的模型, 在系列旁标注「声明」, 其详情会解释这意味着什么。
- 列表有缓存 ([`discovery.cacheTtl`](settings.md#参考)); 「同步模型」按钮立即重新询问服务器。

### 生效参数

每行低调的「检查」操作打开模型检查器 - 一个侧面板, 分「参数」「能力」「定价」三个区块。参数区块回答一个问题: 发往这个模型的请求实际会携带什么?

- 表格列出匹配该模型的每个已配置参数、它的值, 以及一枚点名来处的徽章 - `条目 gpt-5*` 或 `设置 *`, 即胜出的[匹配器](models.md#模型匹配)。当更具体的匹配或更高的层覆盖了另一个值时, 落败的值以删除线显示在下方, 所以在你意料之外触发的匹配器一眼就能找到元凶。
- 被强制的字段标记为强制: 它们连聊天客户端的运行时选项都会胜过 ([完整优先级](models.md#参数))。
- 扩展拒绝转发的键 (提供程序拥有的字段、以 `_` 开头的键) 以弱化样式呈现并注明原因。
- 一行 `max_tokens` 始终在场, 说明该值及其来处: 你的配置、服务器声明的输出限制, 还是封顶的默认值。
- 区块末尾把模型的记录匹配链摆在明面上, 每层一条「记录路径」, 其中每个键都能跳进拥有它的编辑器。

面板由请求路径运行的同一套解析代码渲染, 所以它不可能偏离真实请求。两样它诚实承认无法展示的东西: 聊天客户端在每个请求上设置的运行时选项 (它们覆盖列出的任何*未强制*参数), 以及推理模型的 Configure Model 选择, 后者由 VS Code 存在自己那边。

### 生效能力

检查器的能力区块回答另一个问题: 扩展认为这个模型能做什么, 为什么?

- 每个能力字段列出解析值和一枚来源徽章 - 某服务器条目或全局 `models.capabilities` 记录 (点名胜出的匹配键)、服务器自己的报告、OpenRouter 目录条目 (显式 `_openrouter_model`, 或按精确 ID 或无歧义的厂商前缀后段的隐式匹配)、「上下文减输出」派生, 或内置默认值 - 起作用的指令以低调的记号标在旁边 (「后备」「匹配」), 被覆盖的值显示在胜出者下方 (完整[优先级](models.md#能力))。
- 表格下方的「输出上限」一行说明输出限制是不设上限发出 (用户设置或服务器声明), 还是封顶 4,096 (猜测的默认值)。
- 记录中的问题 - 无效值、无效的正则匹配器、目录不认识的 `_openrouter_model` ID - 在这里、在受影响的行旁边指出。扩展不消费的字段名得到的是一条建议性说明 - 该值照样作为覆盖应用, 而且只有当服务器自己的 `/model/info` 键集已知、非空且不含该名字时才显示 ([能力字段](models.md#能力字段))。
- 区块末尾同样有自己的「记录路径」一行, 即能力记录的匹配链。

它由注册路径运行的同一个解析器渲染, 所以它显示的就是告诉 Copilot Chat 的内容。

## 服务器页上的用量

支出对预算就在每个服务器的行上: 收起的行带着百分比和计量条, 展开该行则列出扩展掌握的每个数字 - 生效预算与密钥报告预算 (两者不同时)、预算的下次重置日期, 以及当服务器提供每日活动数据时的请求数、成功率和缓存命中率。服务器没有报告的字段呈现为一个暗淡的短横线加就地写明的原因, 从不是零。LiteLLM 不跟踪支出的服务器 (没有数据库) 只显示一个空的支出单元格; 被拒绝读取用量数据的密钥保留其行, 并在行下以问题行说明这次拒绝。区块标题里的「立即刷新」按钮立即获取 (获取进行中时禁用); 过期数据保持可见, 原因已知时标注原因 (数字旁的「已过时」, 或点名刷新失败或拒绝的问题行)。当一次显式刷新在每个服务器上都失败时, 会有一条警告弹窗说明; 按服务器的详细信息留在各行上。

打开仪表板只在一次获取到期时才获取用量数据 - 本次会话还没有完成过一轮、距上一轮完成已超过轮询间隔, 或 `servers` 设置在其后有变更; 否则只是照原样渲染已存储的数字。深入内容 - 扩展读什么、从哪里读、两个预算来源如何互动、轮询与新鲜度、警报阈值、状态栏项 - 在[用量与预算](usage.md)页面。

## 功能

功能区块把扩展在聊天之外做的一切放在一页上, 每个功能一组, 页面自带筛选框。每个控件都是普通设置 ([参考](settings.md#参考)), 所以这一页和 settings.json 是同一份文件的两个视图。

- **内联补全**、**提交消息生成**、**PR 描述生成**、**咨询工具**、**快速修复**、**评审评论**和**聊天参与者 (@litellm)** 是已发布的功能: 各自带启用复选框、有模型的还带模型选择器, 以及自己的行 - 内联语言过滤器的模式与列表、提交提示词。模型选择器提供「未设置」加上每个已声明条目所提供的 (server, model) 组合, 以及「自定义模型 ID...」用于发现列不出的模型 (首先是补全模式的 FIM 模型)。内联、PR、咨询、快速修复和评审的模型行带**测试模型**: 一次探测运行该功能所走的完全相同的管线 - 幽灵文本、固定的示例分支、固定问题、针对一条固定示例诊断的快速修复后备路径, 或是一小段固定的示例差异 - 以计数或分类错误作答, 绝不返回模型自身的文本。快速修复的模型只支撑后备路径; 它的聊天路径和参与者一样, 使用聊天选择器指定的模型, 这也是两者都没有决定该模型的模型行的原因。
- 模型选择由已声明条目的 label 加原始模型 ID 组成; 外部组没有条目 label, 因此它们的模型从不出现在选项中 ([功能模型设置](settings.md#参考))。

## 设置

设置区块渲染原生设置编辑器显示的那些设置, 按其分区顺序排列 (模型、聊天、发现、用量、UI; `servers` 不含标量设置, 在[服务器](#服务器)页和[服务器表单](#服务器表单)中管理, 各功能的设置在[功能](#功能)页), 以表单行呈现, 带单位、默认值和「重置」操作。已配置的行会说明其值存放在哪里 (「已在用户设置中修改」); 「重置」从该作用域删除值, 让下一作用域的值或默认值显现。

- 对象形态的设置 - [`models.parameters`](settings.md#参考) 和 [`models.capabilities`](settings.md#参考) - 在这里获得匹配器表格, 因为原生设置 GUI 无法编辑对象。它们使用与[服务器表单](#服务器表单)的每服务器区块相同的表格: 每个匹配器一行, 按从宽到窄排序 (捕获全部的键在顶部, 精确 ID 在底部 - 仅是显示顺序; 存储的键顺序从不改变), 字段呈现为带强制/后备/可继承徽章的字段片, 字段片弹出层用于快速编辑, 铅笔图标打开完整的匹配器编辑器。能力字段名是自由的, 带着与服务器表单同款的建议性笔误提示。每个字段都解析通过之前,「应用」保持禁用。(自定义 HTTP 标头是按服务器的, 不是全局的: 它们存放在条目上, 在[服务器表单](#服务器表单)中编辑。)
- 由于 VS Code 跨作用域合并对象设置, 每个记录编辑器一次只操作一个作用域 (你的编辑写入的那个), 其他作用域的条目以只读列出, 所以应用更改永远不会把用户作用域的值复制进工作区文件。
- [`models.openRouterCatalog`](models.md#openrouter-目录) 行携带一条状态线 - 目录的大小和上次更新时间 - 和一个「刷新」按钮 (与 "LiteLLM: Refresh OpenRouter Catalog" 相同的操作)。设置关闭时该行休眠并附提示; 刷新失败在状态线中报告, 从不弹窗。
- **UI** 组承载仪表板自己的外观: 一个主题选择器 (跟随编辑器主题, 或固定浅色/深色) 和四个强调色色块。两者都在你选中的那一刻生效, 也都是普通设置 - 在 settings.json 中编辑 [`ui.theme`](settings.md#外观) 或 [`ui.accent`](settings.md#外观), 打开着的仪表板同样会换装。无论选了哪一项, 高对比度主题始终跟随编辑器。
- 末尾的**「导入与导出」**组有两个按钮, 「导出设置」和「导入设置」- 与 "LiteLLM: Export Settings..." 和 "LiteLLM: Import Settings..." 命令相同的流程, 用于把你的配置搬到另一台机器 ([详情](settings.md#导出与导入))。

## 诊断

诊断区块汇集支持界面; 命令面板中的 "LiteLLM: Show Diagnostics" 把仪表板直接打开到它。

- 页头的操作就是支持工具: **测试连接**、**打开输出日志**、**复制诊断信息**和**报告 Bug**。旧版本在这里汇总的每服务器连接情况, 如今在[服务器](#服务器)页各自的行上; 「复制诊断信息」仍会把它们收进一整块纯文本, 供粘贴进 Bug 报告 - 导航栏显示的同一结论、已配置服务器数量、以绝对时间戳表示的上次检查、以及每个服务器一行结果 ("OK (12 models)", 否则是错误文本)。这块文本还带着配置诊断的各行, 以及有提供程序组被隐藏时的 "Hidden provider groups" 计数。
- 配置诊断: 扩展在你的设置中发现的问题, 每个都在这里以及它关涉的行旁边呈现 ([下文](#配置诊断))。
- 「报告 Bug」打开预填版本、平台和近期日志的 GitHub Issue - 与导航栏按钮相同的操作。
- 「请求功能」「为扩展评分」「文档」和「GitHub 仓库」是普通链接。

### 已解析模型

诊断区块还渲染扩展预计算的解析表 - 每个已注册模型最终得到的确切能力和参数, 覆盖所有服务器, 早于任何请求。同一份数据的两个视图:

- **继承树**: 你的匹配键画成一棵树 - 每条记录挂在它的下一个更宽匹配之下, 模型作为叶子挂在最具体的匹配之下 - 每个节点标出自己的字段、`_inheritable` 标记, 以及画在被切断分支上的 `_inherit_from: false` 屏障。一眼回答「gpt-5.6 的 temperature 为什么是这个」: 沿它的分支向上走。

```text
*  temperature 0.7, top_p 0.9  (inheritable)
├─ gpt-5*  temperature 0.3  (inheritable)  [inheritance stops here]
│  ├─ gpt-5.6  max_tokens 8192   -> 8192 - 0.3
│  └─ gpt-5, gpt-5.7, ...        -> 0.3
├─ claude-4  temperature 1.0     -> 1.0 - top_p 0.9
└─ (everything else)             -> 0.7 - 0.9
```

- **扁平表**: 每模型一行, 列出最终解析值, 每个值带来源标签片 (自有、由胜出记录继承、强制、后备、服务器、目录、底线), 一个筛选框 (按模型 ID 或匹配键 - 「显示 `gpt-5*` 碰过的一切」), 以及逐行的「检查」操作, 就地打开该模型的[检查器](#生效参数), 覆盖在诊断页之上。

关于树的一条诚实说明: 它是对着你的服务器*此刻*提供的模型画的。记录节点 - 尤其是正则键 - 显示的是它当前匹配到的现存模型, 不是它可能匹配的一切, 所以模型列表变了树也会变。要得到关于某一个模型的权威答案, 扁平表的该模型行和检查器才是正典视图。

完全没有配置匹配记录时, 扁平表仍列出每个模型 - 值随即来自服务器、目录和内置底线 - 树则塌缩为挂在隐式根下的模型, 附一条「不存在记录」的提示。

两者渲染的都是请求路径使用的同一张预计算表, 所以你看到的就是将要发送的。该视图只存在于仪表板本地 - 从不包含在 GitHub 问题报告中。

### 配置诊断

设置问题从不无声失败; 每一个都作为诊断呈现, 带出问题的键和修复方法:

| 诊断 | 含义 | 修复 |
|---|---|---|
| 无效的正则匹配器 | 一个 `/斜杠包裹/` 的记录键无法解析为正则表达式; 该键被忽略 | 修正模式 ([匹配](models.md#模型匹配)) |
| 不可强制的键 | `_force` 点名了提供程序拥有的字段, 任何东西都不得覆盖它; 对该字段的强制被忽略 | 把该字段从强制列表中去掉 ([参数](models.md#参数)) |
| 身份验证配置错误 | 某服务器条目配置了多于一种身份验证形式; 修复前条目不被使用 | 恰好保留一种形式 ([身份验证](servers.md#身份验证)) |
| 旧版限定键 | 某全局记录键仍在使用已移除的 `"<baseUrl>/matcher"` 服务器限定语法; 它永远匹配不到模型 ID, 处于休眠 | 移入那个服务器条目自己的记录 ([迁移](models.md#从前缀键迁移)) |
| 休眠的全局标头 | 迁移在已移除的全局 `headers` 设置中发现了值, 却没有可接收它们的服务器条目; 它们没有应用到任何东西 | 把标头加到服务器条目上, 然后删除旧的全局设置 ([迁移](settings.md#重命名与移除的设置)) |
| 未知的 `_inherit_from` 键 | `_inherit_from` 列表点名了不存在的记录键; 跳过该名字, 列表其余部分照常生效 | 把名字改成精确的记录键 ([匹配](models.md#哪条记录生效)) |
| 未识别的能力字段 (建议性) | `models.capabilities` 记录设置了扩展不消费的字段, 且服务器观察到的 `/model/info` 键中没有它; 该值按原样作为覆盖应用 | 若是笔误就改正拼写; 若是有意为之就保留 ([能力字段](models.md#能力字段)) |

## 状态栏项

扩展最多拥有两个状态栏项; 仪表板是它们的点击落点。

- **连接项**在一切健康时读作 `$(check) LiteLLM`, 工具提示里有服务器和模型数量; 错误和部分状态会改变图标和工具提示, 而工具提示的行是为粘贴进问题报告而写的。单击它打开仪表板。(旧版本把模型数放在项的文本里; 现在它在工具提示里, 让状态栏保持安静。)
- **用量项**显示最差新鲜服务器的支出百分比, 只在有可信内容时出现; 单击它打开[服务器](#服务器)页, 每行都带着自己的支出。它的完整行为 - 模式、阈值、新鲜度规则 - 在[用量与预算](usage.md#状态栏)中规定。
