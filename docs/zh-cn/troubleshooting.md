# 故障排除

[English](../troubleshooting.md) | 简体中文 | [繁體中文](../zh-tw/troubleshooting.md)

扩展把状态放在你看得见的地方: 状态栏项一眼展示连接, 仪表板的诊断标签页给出细节, 输出通道提供完整日志。本页介绍这些工具、问题报告与隐私、超时与重试语义、常见故障、卸载时的清理, 以及从旧版本迁移的说明。

## 状态栏

LiteLLM 状态栏项 (右下角) 显示你的连接状态:

| 图标 | 状态 | 说明 |
|------|--------|-------------|
| `⚠ LiteLLM` | 未配置 | 没有配置服务器 - 单击进行设置 |
| `⟳ LiteLLM` | 正在加载 | 正在从服务器获取模型 |
| `✓ LiteLLM (N)` | 已连接 | 所有服务器可达, 共 N 个可用模型 |
| `⚠ LiteLLM (N)` | 已降级 | 部分服务器不可达, N 个模型来自可达的服务器 |
| `✗ LiteLLM` | 错误 | 所有服务器都失败了 - 诊断标签页有每个服务器的错误 |

随时单击它可打开[仪表板](dashboard.md); 其诊断标签页有详细信息。

## 诊断工具

| 工具 | 它给你什么 |
|------|-------------------|
| 「LiteLLM: 测试连接」(命令面板) | 端到端验证服务器: 连接、报告找到的模型数量、失败时显示详细错误消息, 并更新状态栏 |
| 「LiteLLM: 显示诊断信息」 | 把仪表板打开到[诊断标签页](dashboard.md#诊断): 整体状态、已配置服务器数量、上次检查时间戳、每个服务器一行结果及其 URL、任何旧版注册表遗留, 以及「测试连接」按钮 |
| 「LiteLLM」输出通道 | 完整日志: 配置变化、模型获取尝试及结果、带完整细节的错误。打开输出面板 (`Ctrl+Shift+U` / `Cmd+Shift+U`), 从下拉列表中选择 "LiteLLM" |
| 「LiteLLM: 帮助与反馈」 | 报告 Bug、请求功能或打开文档的快捷入口; 诊断标签页带有同样的链接 |

## 报告问题

「报告问题」操作会打开预填了诊断信息的 GitHub Issue:

- 扩展和 VS Code 版本、平台和连接状态
- 是否配置了 API 密钥和基础 URL: 是、否, 或当凭据由 VS Code 管理时为未知; 从不包含值本身
- 最近的错误和近期日志行

扩展的日志记录的是所发生事件的分类, 从不记录源自服务器响应的文本, 因此预填的正文不可能泄露你的提示、补全或凭据; 即便如此, Issue 会在浏览器中打开, 供你在提交前审阅。当诊断信息对 URL 而言过大时, 全文改为进入你的剪贴板 (可能时还有一个本地文件), Issue 正文会说明省略了什么。

## 隐私与数据

你的提示、附件和补全只在 VS Code 与你配置的终结点之间传输:

- 聊天和模型发现请求发往你的 LiteLLM 服务器的基础 URL。
- OAuth 凭据只发往服务器条目上设置的令牌终结点。
- 扩展没有遥测, 也没有自己的后端; 不向发布者发送任何内容。
- 唯一的另一个出站通道是[问题报告器](#报告问题), 它在本地准备一切, 携带环境细节和扩展自身的日志 (版本、平台、连接状态、错误分类和堆栈 - 从不含提示或响应文本, 从不含密钥值), 并在浏览器中打开, 供你在提交前审阅。

凭据存放在哪里、机器之间同步什么, 见[服务器](servers.md#密钥与密钥存储)。

## 超时与重试

两个超时设置是整个调用的硬性上限, 包含流式传输和任何重试; 其默认值见[设置](settings.md#请求超时)。

- 模型发现请求是幂等的 GET, 因此失败的请求会重试 (最多两次, 整个调用仍受 `discoveryTimeout` 约束)。
- 聊天补全从不重试: 补全可能有副作用 (花费、工具调用), 因此扩展呈现失败, 而不是悄悄为第二次尝试付费。如果长请求被截断, 请调大 `requestTimeout`。
- 当后台模型刷新失败, 但最近一次成功发现还很近 (不足十分钟) 时, 扩展继续提供最后已知的模型列表, 以警告图标标记为过期, 而不是在会话中途丢掉你的模型。

## 常见问题

**「聊天界面或 "Manage Models..." 不见了」**
- 本扩展接入的是 GitHub Copilot Chat; 没有它就没有聊天视图, 也没有模型选择器
- 安装 GitHub Copilot Chat 扩展, 登录 GitHub, 并确保它已启用
- VS Code 较旧时请更新: 扩展需要 1.129.0 或更高版本

**「模型选择器中没有出现任何模型」**
- 查看状态栏 - 它显示实际状态
- 运行「LiteLLM: 测试连接」验证你的设置
- 查看「LiteLLM」输出通道中的错误详情
- 确认你的 LiteLLM 服务器正在运行且可访问

**「服务器返回了 0 个模型」**
- 你的 LiteLLM 代理在运行, 但没有配置任何模型
- 检查你的 LiteLLM 代理配置 (`litellm_config.yaml`)
- 运行 `litellm --config your_config.yaml`, 以带着模型启动代理

**「我的嵌入或图像生成模型没有出现在选择器中」**
- LiteLLM `model_info.mode` 指向非聊天终结点 (`embedding`、`image_generation`、`audio_speech`、`audio_transcription`、`rerank`、`moderation`) 的模型被有意排除在聊天选择器之外, 因为对它们的聊天请求只会失败; 未声明 mode 的模型始终注册
- 代理已暂停的部署 (`model_info.blocked`) 同样被跳过
- 参见[模型与能力](models.md#哪些模型会注册)

**「附加的图像从未到达模型」**
- 图像 (附件, 以及从此前轮次重放的图像) 只发送给在 LiteLLM 模型信息中声明视觉支持 (`supports_vision`) 的模型
- 在其他模型上, 文本照常通过, 图像被丢弃, 并在「LiteLLM」输出通道中留下一条说明
- 参见[模型与能力](models.md#多模态输入)

### 「身份验证失败」
- 两条 401 消息指向不同的凭据。单纯的「身份验证失败: 你的 LiteLLM 服务器需要 API 密钥」意味着代理拒绝了扩展的密钥: 运行「管理 LiteLLM 提供程序」并编辑服务器来更新它, 并对照你的 LiteLLM 代理配置核实密钥
- 「上游身份验证失败」意味着代理接受了你的密钥, 但无法向模型的上游提供方完成身份验证; 更新扩展的密钥无济于事。请在 LiteLLM 服务器上修复该提供方的凭据, 或请服务器运营者修复

### 「连接错误: 无法连接」
- 确认基础 URL 正确 (例如 `http://localhost:4000`)
- 如果你粘贴了以 `/v1` 结尾的 URL, 请去掉该后缀: 扩展会自行追加 `/v1`, 因此 `/v1` 基础 URL 会请求 `/v1/v1/...` 并失败
- 确保你的 LiteLLM 代理正在运行
- 检查防火墙/网络设置

### 「LiteLLM API 错误: 404」/「返回了 404 - 它有响应, 但在此地址上并不提供 LiteLLM API」
- 有东西在该地址应答, 但不是 LiteLLM 代理: 检查那里实际监听的是什么 - 一个 Web 服务器、别的服务, 或者端口不对 (LiteLLM 代理的默认端口是 4000)
- `/v1` 陷阱同样适用于这里: 以 `/v1` 结尾的基础 URL 会让扩展请求 `/v1/v1/...`, 代理对此回答 404。去掉该后缀; 扩展会自行追加 `/v1`
- 之前正常的服务器在聊天请求上返回 404, 通常意味着该模型已从代理中移除: 运行「LiteLLM: 立即同步模型」刷新模型列表。如果所有请求都以 404 失败, 请按上面的方法检查基础 URL

**「消息超出 token 限制 (估计 N 个 token, 限制为 M)」**
- 当扩展自己的 token 估算超出模型的输入预算时, 它会在发送前拒绝请求。该计数是本地估算 (文本约四个字符一个 token, 图像、PDF 或音频剪辑按固定数值计), 因此可能与服务器实际计费的不同
- 精简对话或去掉附件, 或者提高预算: 限制来自服务器声明的输入限制, 服务器未声明时来自 [`defaultContextLength`/`defaultMaxInputTokens` 设置](settings.md#token-限制)

**「模型只生成了推理输出, 而此版本的 VS Code 无法显示它」**
- 你的 VS Code 构建缺少思维部分 API, 因此流式推理被丢弃 (输出通道中有说明), 只包含推理的回复会以此错误失败
- 将 VS Code 更新到支持思维部分的版本, 或改用会返回最终文本的模型

## 已删除的服务器、隐藏的组与遗留的原生组

VS Code 的提供程序组 API 可以添加组但无法删除组, 因此当某个 `servers` 条目消失时, 扩展无法删除它的组。删除通过隐藏来实现:

- 删除条目 (仪表板的「删除」, 或从 settings.json 中删掉它) 会隐藏其组: 该组不再提供模型, 仪表板把它列在弱化显示的「N 个隐藏的组」一行下, 每行带「取消隐藏」。通知会点名该组, 并提议打开模型文件。
- 删除外部行 (没有设置条目的组) 效果相同: 该行的「删除」隐藏该组, 后续通知带有同样的步骤。
- 组的空壳在宿主侧仍然存在。要彻底删除: 打开模型文件 (通知的按钮, 或手动打开 `<profile>/User/chatLanguageModels.json`), 从 JSON 数组中删除该组的对象, 重新加载窗口, 然后运行「LiteLLM: 立即同步模型」。
- 手动兜底: 这些组存放在你 VS Code 用户数据下的 `<profile>/User/chatLanguageModels.json` 中; 删除一个组就是从该 JSON 数组中删除它的对象。请先完全退出 VS Code - 它在启动时读取该文件并驻留内存, 运行期间所做的编辑会被覆盖。
- 重命名条目会以新名称创建一个新组; 旧组保留其模型, 直到你以同样的方式删除它。仪表板把它显示为一个外部行, 其徽章提示注明这次重命名。
- 当你重新添加具有其标签和基础 URL 的条目, 或通过隐藏组一行的「取消隐藏」时, 隐藏的组会回来。
- 当扩展记录过来历时, 外部行的徽章提示会说明组的来源 - 已删除条目的遗留, 或重命名的遗留。在此扩展之外添加、或早于此跟踪的组, 显示普通的默认提示。

## 每服务器模型参数未生效

当服务器条目声明了每条目 `modelParameters`, 但为该服务器提供服务的 VS Code 提供程序组不带有条目的标签化标识时, 仪表板会显示「参数未生效」徽章 (以及点名受影响条目的横幅)。这发生在组早于条目标签, 或重命名或基础 URL 编辑留下过期组时; 经过这种组的请求只获得全局 `modelParameters` 设置。

两种修复方法:

- 从模型文件 (`<profile>/User/chatLanguageModels.json`) 中删除该组的对象, 重新加载窗口, 并运行「LiteLLM: 立即同步模型」; 扩展会从条目重新创建该组, 这次带上它的标识。
- 或者用新标签保存条目; 会为它创建一个新组。旧组保留, 直到你从模型文件中删除它的对象。

## 标签限定的参数键已迁移

0.3.1 及更早版本支持按服务器标签限定 `modelParameters` 键 (`Production/gpt-4`)。标签限定已经移除; 替代方案是匹配的 `servers` 条目上的每条目 `modelParameters`, 以及基础 URL 限定 (`https://litellm.example.com/gpt-4`); 参见[模型参数](model-parameters.md)。

扩展自动重写了用户设置中的键, 每台机器一次:

- 标签与某个声明的 `servers` 条目匹配 (且基础 URL 相同) 的标签限定键, 被复制进该条目的 `modelParameters`, 键为纯模型前缀。条目中已存在的键不会被覆盖; 迁移后你从条目中删除的键保持删除状态。
- 否则, 参数被复制到全局设置中一个基础 URL 限定的键, 与原键并存。

两种情况下原键都被保留: 像 `openai/gpt-4o` 这样的键可能是纯模型前缀而非标签限定, 两种读法无法区分, 因此迁移采用复制而非移动。标签匹配移除后, 原键就只是普通的纯前缀键了。

工作区或文件夹设置中的标签限定键不会被触碰 (那些文件是共享的; 扩展只记录发现了多少个)。请手动移动它们, 要么移入条目的 `modelParameters`, 要么改为 `<baseUrl>/<model prefix>` 形式。

## 卸载与清理

卸载扩展不会删除两样东西, 如果你在意遗留的凭据, 请先清理:

- 你的 `litellm-vscode-chat.*` 设置留在 settings.json 中, 包括 `servers` 条目中的任何内联 API 密钥、OAuth 客户端密钥或虚拟密钥, 以及 `headers` 中的任何网关密钥。在设置编辑器中删除它们, 或从用户 settings.json 中删掉相应行。
- 服务器同步成的 VS Code 提供程序组归宿主所有, 保留凭据的自有副本, 直到你删除它们: 从 `<profile>/User/chatLanguageModels.json` 中删除它们的对象 (之后退出或重新加载 VS Code)。

存放在 VS Code 密钥存储中的密钥可以在扩展仍安装时删除, 通过编辑表单的「保存时删除已存储的...」复选框 ([服务器](servers.md#密钥与密钥存储)); 卸载之后, 该存储归 VS Code 的扩展数据处理所有, 无法再从扩展自身的 UI 访问。
