# 疑難排解

延伸模組把狀態放在您看得到的地方: 狀態列項目一眼呈現連線、儀表板的診斷分頁提供細節、輸出通道提供完整記錄。本頁涵蓋這些工具、問題回報與隱私、逾時與重試語意、常見的失敗情況、解除安裝時的清理, 以及舊版本的移轉說明。

## 狀態列

LiteLLM 狀態列項目 (右下角) 顯示您的連線狀態:

| 圖示 | 狀態 | 說明 |
|------|--------|-------------|
| `⚠ LiteLLM` | 尚未設定 | 沒有設定任何伺服器 - 按一下即可設定 |
| `⟳ LiteLLM` | 載入中 | 正在從伺服器擷取模型 |
| `✓ LiteLLM (N)` | 已連線 | 所有伺服器都可連線, 共 N 個可用模型 |
| `⚠ LiteLLM (N)` | 部分異常 | 部分伺服器無法連線, 可連線的伺服器提供 N 個模型 |
| `✗ LiteLLM` | 錯誤 | 所有伺服器都失敗 - 診斷分頁有各伺服器的錯誤 |

隨時按一下它即可開啟[儀表板](dashboard.md); 其診斷分頁有詳細資料。

## 診斷工具

| 工具 | 提供什麼 |
|------|-------------------|
| 「LiteLLM: 測試連線」(命令選擇區) | 端對端驗證伺服器: 連線、回報找到的模型數、失敗時顯示詳細錯誤訊息, 並更新狀態列 |
| 「LiteLLM: 顯示診斷」 | 開啟儀表板的[診斷分頁](dashboard.md#診斷): 整體狀態、已設定伺服器數、上次檢查時間戳記、每個伺服器一行結果與其 URL、任何舊版登錄殘留, 以及「測試連線」按鈕 |
| 「LiteLLM」輸出通道 | 完整記錄: 設定變更、模型擷取的嘗試與結果, 以及帶完整細節的錯誤。開啟輸出面板 (`Ctrl+Shift+U` / `Cmd+Shift+U`), 從下拉選單選取 "LiteLLM" |
| 「LiteLLM: 說明與意見回饋」 | 回報錯誤、建議功能或開啟文件的捷徑; 診斷分頁有相同的連結 |

## 回報問題

「回報問題」動作會開啟預先填入診斷的 GitHub 問題:

- 延伸模組與 VS Code 版本、平台與連線狀態
- 是否設定了 API 金鑰與基底 URL: 是、否, 或當認證由 VS Code 管理時為未知; 絕不包含值本身
- 最近一次錯誤與近期記錄行

延伸模組的記錄只記載事件的分類, 從不記載衍生自伺服器回應的文字, 所以預填的內文不可能洩漏您的提示、完成內容或認證; 儘管如此, 問題會在您的瀏覽器中開啟, 供您在送出前檢閱。當診斷過大無法放進 URL 時, 完整文字會改為送到剪貼簿 (可能的話也存成本機檔案), 問題內文會說明省略了什麼。

## 隱私與資料

您的提示、附件與完成內容只在 VS Code 與您設定的端點之間傳輸:

- 聊天與模型探索請求送往您 LiteLLM 伺服器的基底 URL。
- OAuth 認證只送往伺服器項目上設定的權杖端點。
- 延伸模組沒有遙測, 也沒有自己的後端; 不會向發行者傳送任何東西。
- 唯一的其他對外介面是[問題回報器](#回報問題), 它在本機準備一切, 攜帶環境細節與延伸模組自己的記錄 (版本、平台、連線狀態、錯誤分類與堆疊 - 絕無提示或回應文字, 絕無金鑰值), 並在您的瀏覽器中開啟供送出前檢閱。

認證存放在哪裡、什麼會在機器間同步, 參閱[伺服器](servers.md#祕密與祕密儲存體)。

## 逾時與重試

兩個逾時設定都是整個呼叫的硬性上限, 包含串流與任何重試; 其預設值參閱[設定](settings.md#請求逾時)。

- 模型探索請求是冪等的 GET, 所以失敗會重試 (最多兩次, 整個呼叫仍受 `discoveryTimeout` 約束)。
- 聊天完成永不重試: 完成可能有副作用 (花費、工具呼叫), 所以延伸模組呈現失敗, 而不是默默為第二次嘗試付費。若長請求被中斷, 請調高 `requestTimeout`。
- 當背景模型重新整理失敗, 但上次成功探索還很近 (不到十分鐘) 時, 延伸模組會繼續提供最後已知的模型清單, 以警告圖示標示為過時, 而不是在工作階段中途丟掉您的模型。

## 常見問題

**「找不到聊天介面或 "Manage Models..."」**
- 本延伸模組接入 GitHub Copilot Chat; 少了它就沒有聊天檢視, 也沒有模型選擇器
- 安裝 GitHub Copilot Chat 延伸模組, 登入 GitHub, 並確認它已啟用
- 較舊的 VS Code 請更新: 延伸模組需要 1.129.0 或更新版本

**「模型選擇器中沒有出現任何模型」**
- 查看狀態列 - 它顯示實際狀態
- 執行「LiteLLM: 測試連線」驗證您的設定
- 查看「LiteLLM」輸出通道的錯誤細節
- 確認您的 LiteLLM 伺服器正在執行且可連線

**「伺服器回傳 0 個模型」**
- 您的 LiteLLM Proxy 在執行, 但沒有設定任何模型
- 檢查您的 LiteLLM Proxy 設定 (`litellm_config.yaml`)
- 執行 `litellm --config your_config.yaml` 以帶著模型啟動 Proxy

**「我的嵌入或圖片生成模型沒有出現在選擇器中」**
- LiteLLM `model_info.mode` 指名非聊天端點 (`embedding`、`image_generation`、`audio_speech`、`audio_transcription`、`rerank`、`moderation`) 的模型是刻意不放進聊天選擇器的, 因為對它們發出聊天請求只會失敗; 未宣告 mode 的模型一律註冊
- Proxy 已暫停的部署 (`model_info.blocked`) 也會被略過
- 參閱[模型與功能](models.md#註冊哪些模型)

**「附加的圖片始終沒有送達模型」**
- 圖片 (附件, 以及先前回合重播的圖片) 只會傳給在 LiteLLM 模型資訊中宣告視覺支援 (`supports_vision`) 的模型
- 在其他模型上, 文字照常送出, 圖片被捨棄, 並在「LiteLLM」輸出通道留下說明
- 參閱[模型與功能](models.md#多模態輸入)

**「驗證失敗」**
- 兩種 401 訊息指的是不同的認證。單純的「驗證失敗: 您的 LiteLLM 伺服器需要 API 金鑰」表示 Proxy 拒絕了延伸模組的金鑰: 執行「管理 LiteLLM 提供者」並編輯伺服器來更新, 並對照您的 LiteLLM Proxy 設定確認金鑰
- 「上游驗證失敗」表示 Proxy 接受了您的金鑰, 但無法向該模型的上游提供者完成驗證; 更新延伸模組的金鑰幫不上忙。請在 LiteLLM 伺服器上修正該提供者的認證, 或請營運者處理

**「連線錯誤: 無法連線」**
- 確認基底 URL 正確 (例如 `http://localhost:4000`)
- 若您貼上的 URL 以 `/v1` 結尾, 請移除該結尾: 延伸模組會自行附加 `/v1`, 所以以 `/v1` 為基底的 URL 會請求 `/v1/v1/...` 而失敗
- 確認您的 LiteLLM Proxy 正在執行
- 檢查防火牆/網路設定

**「訊息超過 token 上限 (估計 N 個 token, 上限 M)」**
- 當延伸模組自己的 token 估計超過模型的輸入額度時, 它會在送出前拒絕請求。這個計數是本機估計 (文字約四個字元一個 token, 圖片、PDF 或音訊剪輯各有固定數字), 所以可能與伺服器實際計費不同
- 縮短對話或移除附件, 或提高額度: 上限來自伺服器宣告的輸入上限, 或在伺服器未宣告時來自 [`defaultContextLength`/`defaultMaxInputTokens` 設定](settings.md#token-上限)

**「模型只產生了推理輸出, 而此版本的 VS Code 無法顯示」**
- 您的 VS Code 版本缺少 thinking-part API, 所以串流的推理被捨棄 (輸出通道會留下說明), 而只包含推理的回覆會以這個錯誤失敗
- 將 VS Code 更新至支援 thinking parts 的版本, 或改用會回傳最終文字的模型

## 移除的伺服器、隱藏的群組與殘留的原生群組

VS Code 的提供者群組 API 能新增群組, 但不能移除, 所以當 `servers` 項目消失時, 延伸模組無法刪除其群組。移除改以隱藏實現:

- 移除項目 (儀表板的「移除」, 或從 settings.json 刪除) 會隱藏其群組: 群組不再提供模型, 儀表板把它列在淡化的「N 個隱藏的群組」一行之下, 每列附「取消隱藏」。通知會點名該群組並提議開啟模型檔案。
- 移除外部列 (沒有設定項目的群組) 也一樣: 該列的「移除」隱藏群組, 後續通知附上相同步驟。
- 群組的空殼仍存在於主機端。要永久刪除: 開啟模型檔案 (通知的按鈕, 或自行開啟 `<profile>/User/chatLanguageModels.json`), 從 JSON 陣列移除該群組的物件, 重新載入視窗, 然後執行「LiteLLM: 立即同步模型」。
- 手動做法: 群組存放在您 VS Code 使用者資料下的 `<profile>/User/chatLanguageModels.json`, 移除一個群組就是從 JSON 陣列刪除其物件。請先完全結束 VS Code - 它在啟動時讀取此檔並保留在記憶體中, 執行期間的編輯會被覆寫。
- 重新命名項目會以新名稱建立新群組; 舊群組保留其模型, 直到您用同樣方式刪除它。儀表板會把它顯示為外部列, 其徽章提示說明這次重新命名。
- 當您重新加入標籤與基底 URL 相同的項目, 或透過「隱藏的群組」一行的「取消隱藏」, 隱藏的群組就會回來。
- 外部列的徽章提示會在延伸模組有記錄時說明群組的來歷 - 已移除項目的殘留, 或重新命名的殘留。在本延伸模組之外新增, 或早於這項追蹤的群組, 顯示一般的預設文字。

## 各伺服器模型參數未生效

當伺服器項目宣告了各項目 `modelParameters`, 但服務該伺服器的 VS Code 提供者群組沒有攜帶項目的標籤身分時, 儀表板會顯示「參數未生效」徽章 (以及點名受影響項目的橫幅)。這發生在群組早於項目標籤, 或重新命名、基底 URL 編輯留下了過時群組時; 經過這種群組的請求只會拿到全域的 `modelParameters` 設定。

兩種修法:

- 從模型檔案 (`<profile>/User/chatLanguageModels.json`) 刪除該群組的物件, 重新載入視窗, 然後執行「LiteLLM: 立即同步模型」; 延伸模組會從項目重新建立群組, 這次帶著其身分。
- 或以新標籤儲存該項目; 會為它建立新群組。舊群組會留著, 直到您從模型檔案刪除其物件。

## 以標籤限定的參數鍵已移轉

0.3.1 以前的版本支援以伺服器標籤限定 `modelParameters` 的鍵 (`Production/gpt-4`)。標籤限定已經移除; 替代方案是對應 `servers` 項目上的各項目 `modelParameters`, 以及基底 URL 限定 (`https://litellm.example.com/gpt-4`); 參閱[模型參數](model-parameters.md)。

延伸模組已自動改寫使用者設定中的鍵, 每台機器一次:

- 標籤與某個宣告的 `servers` 項目相符 (且基底 URL 相同) 的標籤限定鍵, 被複製進該項目的 `modelParameters`, 以純模型前置詞為鍵。項目中已存在的鍵不會被覆寫, 而移轉後被您從項目刪除的鍵會保持刪除。
- 其他情況下, 參數被複製到全域設定中以基底 URL 限定的鍵, 與原鍵並存。

兩種情況都保留了原始的鍵: 像 `openai/gpt-4o` 這樣的鍵可能是純模型前置詞而非標籤限定, 兩種解讀無法區分, 所以移轉採複製而非搬移。標籤比對移除後, 原始的鍵就單純又是純前置詞鍵了。

工作區或資料夾設定中的標籤限定鍵不會被更動 (那些檔案是共用的; 延伸模組改為記錄找到了幾個)。請手動搬移它們, 放進項目的 `modelParameters`, 或改成 `<baseUrl>/<model prefix>` 形式。

## 解除安裝與清理

解除安裝延伸模組不會移除兩樣東西, 所以若您在意殘留的認證, 請先清理:

- 您的 `litellm-vscode-chat.*` 設定會留在 settings.json 中, 包括 `servers` 項目裡任何內嵌的 API 金鑰、OAuth 用戶端密碼或虛擬金鑰, 以及 `headers` 裡任何閘道金鑰。請在設定編輯器中移除, 或從使用者 settings.json 刪除那些行。
- 伺服器同步出去的 VS Code 提供者群組由主機擁有, 會保留自己的認證副本, 直到您移除它們: 從 `<profile>/User/chatLanguageModels.json` 刪除其物件 (之後結束或重新載入 VS Code)。

存放在 VS Code 祕密儲存體的祕密, 可以趁延伸模組還安裝時, 透過編輯表單的「儲存時移除已儲存的...」核取方塊移除 ([伺服器](servers.md#祕密與祕密儲存體)); 解除安裝之後, 那份儲存體歸 VS Code 的延伸模組資料處理管轄, 延伸模組自己的 UI 就再也搆不到了。
