# 儀表板

「LiteLLM: 開啟儀表板」開啟一個包含一切的面板: 伺服器、已探索的模型與延伸模組的設定, 上方是顯示整體連線狀態的狀態條。它是延伸模組其餘部分所用同一批儲存區的一個檢視, 所以在這裡做的任何事, 都同樣可以透過 VS Code 設定與命令完成; 儀表板只是把它們集中一處。

## 版面配置

- 頂端的狀態條: 整體連線狀態、伺服器與模型數、上次同步時間, 以及「同步模型」按鈕。標題旁有個低調的「回報錯誤」動作, 會開啟預先填入版本、平台與近期記錄的 GitHub 問題。
- 三個分頁。伺服器與模型共用第一個, 因為它們是同一條工作流程: 連線伺服器, 看到它的模型。第二個以可編輯的表單控制項呈現延伸模組的設定。第三個是診斷: 連線摘要, 加上意見回饋與文件連結。
- 設定編輯會寫入您的 VS Code 設定 (寫入值已經設定的範圍, 否則寫入使用者設定), 按鈕執行的則是命令選擇區提供的同一批命令。

## 伺服器

伺服器清單顯示延伸模組知道的每個伺服器: 在 `litellm-vscode-chat.servers` 設定中宣告的項目, 以及只以 VS Code 提供者群組形式存在的「外部」伺服器 (在本延伸模組之外新增)。

每一列的狀態膠囊是四種狀態之一:

| 狀態 | 意義 |
|--------|---------|
| 已連線 | 探索成功 |
| 錯誤 | 上次檢查失敗 |
| 同步問題 | 伺服器有回應, 但最近一次設定同步回報了問題, 通常是[群組更新限制](servers.md#servers-設定) |
| 尚未檢查 | 已宣告, 但尚未經過任何探索 |

「錯誤」或「同步問題」狀態背後的錯誤文字會以可選取的形式呈現在表格下方的橫幅中; 復原步驟參閱[疑難排解](troubleshooting.md)。

新增/編輯表單在側邊面板開啟; 它寫入的是 servers 設定, 所以在這裡的編輯與在 settings.json 的編輯是同一件事。「儲存」旁的「測試連線」會在您提交前探測草稿 - 用目前輸入的 URL 與認證發出一次探索呼叫, 回答「已連線 - 12 個模型」或確切的錯誤, 且不儲存任何東西。對外部列按「編輯」會把它採用進設定; 參閱[伺服器](servers.md#外部伺服器與採用)。

對每個祕密欄位, 表單讓您在 VS Code 祕密儲存體 (預設) 與內嵌設定值之間選擇:

- 祕密儲存體中的祕密永遠不會回顯到儀表板; 表單顯示的是值存放在哪裡, 而不是值本身。
- 內嵌值會預填到編輯表單, 並以「顯示」切換遮罩: 它們本來就以純文字存在您的 settings.json 中, 所以表單不會揭露設定編輯器看不到的東西。
- 編輯時, 清空的祕密欄位會保留已儲存的值; 刪除祕密要用表單明確的「儲存時移除已儲存的...」核取方塊 (參閱[祕密與祕密儲存體](servers.md#祕密與祕密儲存體))。

### 通知

- **「參數未生效」** (伺服器列上的徽章, 加上表格下方對應的橫幅): 項目宣告了各伺服器模型參數, 但服務它的提供者群組沒有攜帶項目的標籤身分 (群組早於項目標籤, 或重新命名留下了過時群組), 所以那些參數沒有被套用。修法是從模型檔案 (chatLanguageModels.json) 刪除該群組的物件、重新載入視窗並重新同步 - 或改用新標籤; 步驟參閱[疑難排解](troubleshooting.md#各伺服器模型參數未生效)。
- **採用外部伺服器之後**, 一次性的通知會提醒您原始群組仍然存在, 在您從模型檔案刪除其物件 (通知的按鈕會開啟它) 並重新載入視窗之前, 其模型會重複出現。

## 模型

您的伺服器回報並已註冊給 Copilot Chat 的每個模型, 呈現在一張可排序、可篩選的表格中, 帶有 token 上限、價格與功能註記。

- 在伺服器表格中按一下某伺服器的模型數, 會把這張表縮小到該伺服器的模型; 篩選框旁的小標籤顯示目前的範圍, 按一下即可清除。
- 每一列都有複製動作 (游標停留時可見), 複製模型的確切 ID, 也就是 [`modelParameters` 前置詞](model-parameters.md#前置詞比對與伺服器限定)比對的對象。
- 清單有快取 ([discoveryCacheTtl](settings.md#模型清單快取)); 「同步模型」按鈕會立即重新詢問伺服器。

表格各欄的來源、每項功能閘控什麼, 以及模型為何可能缺席, 參閱[模型與功能](models.md)。

### 有效參數

每一列低調的「參數」動作 (游標停留時可見) 會開啟一個側邊面板, 回答一個問題: 送往這個模型的請求實際上會帶什麼?

- 表格列出比對到該模型的每個已設定參數、其值, 以及由哪一層設定 - `伺服器項目「Team A」- gpt-4` 或 `設定 - gpt-4`, 點名獲勝的前置詞鍵。較高層覆寫較低層時, 落敗的值以刪除線顯示在下方。
- 當伺服器限定的設定鍵獲勝時, 它取代掉的整筆未限定記錄會列為「未套用」- 限定鍵是整筆取代記錄, 不與其合併 (參閱[前置詞比對](model-parameters.md#前置詞比對與伺服器限定))。
- 延伸模組拒絕轉送的鍵 (提供者擁有的欄位、以 `_` 開頭的鍵) 以淡化樣式呈現並附上原因。
- `max_tokens` 一行永遠存在, 說明其值與來源: 您的設定、伺服器宣告的輸出上限, 或加上限的預設值。

這個面板由請求路徑執行的同一套解析程式碼繪製, 所以不可能與真實請求脫節。有兩件事它誠實地無法顯示: 聊天用戶端對每個請求設定的執行階段選項 (它們覆寫所列的任何轉送參數), 以及推理模型在「設定模型」(Configure Model) 中的選擇, 那由 VS Code 存放在它那一側。

## 設定

設定分頁以表單列呈現原生設定編輯器顯示的同一批設定, 附預設值與「重設」動作。

- 有兩個設定在這裡比在設定 UI 好編輯: `modelParameters` 與 `headers` 是原生設定 GUI 無法編輯的物件, 所以儀表板為它們提供列編輯器。
- 模型參數的值是 JSON (`0.2`、`true`、`"text"`、`["stop"]`); 無效的輸入會被標示, 在每一列都能剖析之前「套用」保持停用。
- 因為 VS Code 會跨範圍合併物件型設定, 每個記錄編輯器一次只作用於一個範圍 (您的編輯寫入的那個), 其他範圍的項目以唯讀列出, 所以套用變更絕不會把使用者範圍的值複製進工作區檔案。
- 標頭值是設定, 不是祕密: 它們的顯示方式與設定編輯器完全相同, 所以含祕密的標頭請放在使用者範圍, 不要放工作區範圍。

## 診斷

診斷分頁彙集各種支援介面; 在命令選擇區執行「LiteLLM: 顯示診斷」會直接開啟儀表板的這個分頁。

- 一份為整段複製進錯誤報告而寫的連線摘要: 與狀態條相同的結論、已設定伺服器數、以絕對時間戳記呈現的上次檢查時間 (附相對時間), 以及每個伺服器一行結果 ("OK (12 models)", 否則為錯誤文字), 加上「測試連線」按鈕。帶有移轉前伺服器且沒有自己列的安裝, 還會看到 "Legacy registry servers" 計數。
- 「回報錯誤」會開啟預先填入版本、平台與近期記錄的 GitHub 問題 - 與標題按鈕相同的動作。
- 「建議功能」、「為此延伸模組評分」、「文件」與 GitHub 儲存庫是一般連結。
